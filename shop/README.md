# Magnat Flower

Внутренний сайт учёта цветочного магазина. Валюта — кыргызский сом (KGS), суммы в базе хранятся в тыйынах. Отчётные сутки — Asia/Bishkek.

## Возможности

- Товары, остатки, минимальный запас и средняя закупочная стоимость.
- Букеты с составом; автоматическое списание цветов при продаже.
- Поступления, продажи, списания, расходы и инвентаризация.
- Редактирование карточек и рецептов с сохранением истории изменений.
- Полный возврат продажи и отмена операций обратным документом.
- Дневные отчёты, выбор даты и итоги за всё время; обновление открытого отчёта раз в минуту.
- Отдельные аккаунты владельца и сотрудников. Владелец добавляет и отключает сотрудников.
- Вход по логину или привязанному телефону, изменение пароля и одноразовые резервные коды восстановления. SMS не подключены.
- Серверная проверка доступа, транзакции, запрет отрицательных остатков и защита от повторного проведения операции.

## Стек

React, TypeScript, Vinext/Vite, Cloudflare Workers, D1 (SQLite), Drizzle, Tailwind и Radix UI.

## Локальный запуск

Нужен Node.js 24 и npm. Все команды выполняются из папки `shop`.

```sh
npm ci
npm run build
```

Для НОВОЙ локальной базы последовательно примените четыре миграции:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_nostalgic_jackal.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_ambitious_hex.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0002_nostalgic_hellcat.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0003_fearless_jamie_braddock.sql
npm run dev
```

Не применяйте уже выполненные миграции повторно. Откройте http://localhost:5173/. При первом запуске создайте владельца через `/login`; локальная имитация входа Sites доступна только для разработки.

Локальная база находится в `.wrangler/state`. Удаление этой папки уничтожает локальные данные. Она не входит в Git.

## Проверка

```sh
node node_modules/typescript/bin/tsc --noEmit
npm run build
```

Интеграционные проверки выполняются при запущенном локальном сервере и применённых миграциях, в отдельной тестовой копии проекта. Создайте папку `work`, если её нет.

```sh
node tests/auth-integration.mjs
node tests/operations.mjs
node tests/report-backup.mjs
```

Проверки создают временные записи и удаляют их после выполнения. `tests/integration.mjs` — старый сценарий до внедрения отдельных аккаунтов; требует адаптации и не входит в актуальный набор.

## Публикация

GitHub Pages обслуживает статические файлы и не запускает серверные API этого приложения. Хранение кода в GitHub само по себе не публикует работающий магазин.

Текущий проект подготовлен для Sites: существующий `project_id` указан в `.openai/hosting.json`. Публикация через Sites создаёт отдельную серверную базу; локальные данные автоматически не переносятся. Сохраните закрытый доступ. Первоначальное создание владельца защищено входом Sites.

Для самостоятельного размещения на Cloudflare Workers нужны реальная база D1, привязка `DB`, применение миграций и замена первоначального входа Sites безопасной процедурой создания владельца. Идентификатор базы в `vite.config.ts` является локальной заглушкой, а не готовой производственной конфигурацией.

## Данные и восстановление

В Git не включаются аккаунты, рабочая база, локальные секреты, журналы и резервные копии. Пароли в базе хешируются bcrypt; сеансы используют HttpOnly cookie и истекают через 8 часов.

Блок скачивания резервной копии убран из интерфейса. Защищённый API выгрузки сохранён; автоматическое копирование по расписанию пока не настроено. Копия содержит хеши паролей и резервных кодов, поэтому её нужно хранить отдельно в защищённом месте.

Проверка и восстановление копии в НОВЫЙ SQLite-файл:

```sh
node scripts/restore-backup.mjs backup.json restored.sqlite
```

Существующий файл не перезаписывается. Импорт в рабочую базу выполняется администратором отдельно.

## Ограничения

Нет частичных возвратов, партий и сроков годности, SMS-восстановления и кассовой фискализации. Прибыль учитывает только внесённые операции и расходы. Журнал интерфейса показывает последние 100 документов; отчёты считают весь выбранный период.
